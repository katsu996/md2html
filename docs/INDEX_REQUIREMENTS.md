# 生成HTMLの目次（index.html）作成・更新機能 要件定義書

- 対象: `md2html` CLIおよびNode.js上のTypeScript / JavaScript公開API
- 詳細設計: [INDEX_DESIGN.md](./INDEX_DESIGN.md)（#18）
- 親設計: [【要件・基本設計】生成HTMLの目次（index.html）作成・更新機能](https://github.com/katsu996/md2html/issues/16)

> 本書は要件定義および基本設計である。具体的なモジュール構成、アルゴリズム、テストコード、実装手順などの詳細設計・実装は本書の対象外とし、後続の詳細設計Issueまたは実装Issueで検討する。

## 1. 目的

`md2html` で個別に生成した複数のHTMLを、ローカルPC上で一つの小規模サイトのように閲覧できるようにする。利用者は `index.html` を入口として各HTMLページへ移動でき、MarkdownをHTMLへ変換する際には必要なタイミングで目次を更新できる。

ローカルフォルダに生成済みHTMLや手作業で追加したHTMLが混在していても、目次を再生成するだけで実在するHTMLページへのリンク一覧を得られる。

## 2. 基本原則

目次の情報源はMarkdownではなく、指定フォルダに**現に存在するHTMLファイル**である。Markdownの有無、変換履歴、HTMLの作成方法は目次への掲載可否に影響しない。

## 3. 用語

| 用語 | 定義 |
| --- | --- |
| 入力Markdown | CLIまたはファイル変換APIで今回指定された `.md` ファイル |
| 出力HTML | 入力Markdownの変換結果として作成するHTMLファイル |
| 出力先フォルダ | 出力HTMLを格納するフォルダ。`--output` を省略した場合は入力Markdownと同じフォルダ、指定した場合は指定先HTMLの親フォルダ |
| 目次 | 出力先フォルダに作成する `index.html`。出力先フォルダ直下の実在HTMLを一覧化するページ |
| 目次対象HTML | 出力先フォルダ直下に存在する `.html` ファイルのうち、目次ファイル自身を除いたもの |

## 4. 対象範囲

### 対象

- CLIにおける `--index` フラグ、目次ページの生成・更新、現在変換したHTMLへの「目次へ戻る」リンク
- TypeScript / JavaScript用の公開API
- 出力先フォルダ直下にあるHTMLを基にした `index.html` の生成・更新

### 対象外

- サブフォルダの再帰走査、Markdownフォルダ全体の一括変換、静的ファイルのコピー、Webサーバー機能、HTMLの削除、既存HTMLの一括書き換え
- カスタムテンプレート、常時表示サイドバー、前へ／次へナビゲーション、検索、タグ・カテゴリ管理

## 5. 機能要件

| ID | 要件 |
| --- | --- |
| FR-01 | `--index` を指定しない限り、既存の単一Markdown→単一HTML変換仕様（`--force` を含む上書き規則）を変更しない。 |
| FR-02 | `--index` を指定した場合、入力MarkdownのHTML変換が正常終了した後にのみ、出力先フォルダの目次を再生成する。変換に失敗した場合は目次を更新しない。 |
| FR-03 | 目次ファイルは生成のたびに更新される成果物であり、既存の `index.html` が存在する場合は上書きする。既存の `--force` 規則を適用しない。 |
| FR-04 | 目次対象HTMLは、出力先フォルダ直下に実在する `.html` ファイルから収集する。入力Markdownの有無、ファイル名の対応、`md2html` による生成履歴、手作業で作成されたかどうかを参照しない。 |
| FR-05 | `index.html` は目次ファイル自身であるため一覧から除外する。HTMLファイルが削除されていれば、次回の目次生成時に一覧から自動的に除外される。本機能はHTMLファイルを削除しない。 |
| FR-06 | 目次対象HTMLはファイル名の昇順で表示する。表示名はファイル名とし、リンク先は同一フォルダ内の相対URLとする。空白、日本語、記号などを含むファイル名でもローカルで正しく遷移できるURL表現を用いる。 |
| FR-07 | 目次ページには既定でタイトル「目次」を表示する。CLIおよび公開APIからサイトタイトルを指定した場合は、その値をページタイトルおよび見出しに用いる。 |
| FR-08 | 目次は各エントリについて、ファイル名へのリンクと、ファイルシステム上の作成日時を実行環境のローカル時刻で `YYYY-MM-DD HH:mm` 形式に整形したものを表示する。 |
| FR-09 | 目次ページは既存の `md2html` が提供する自己完結HTMLとして扱い、ローカルファイルとして直接開けるものとする。静的ファイル（画像、CSS、PDF等）はコピーしない。 |
| FR-10 | `--index` を指定して変換した出力HTMLには、同じ出力先フォルダにある `index.html` へ戻るリンクを追加する。表示文言は「目次へ戻る」とする。 |
| FR-11 | FR-10のリンク追加の対象は、当該コマンドで今回変換した出力HTMLのみとする。すでに存在するHTML、手作業で作成されたHTML、公開APIによる目次のみの更新時に発見したHTMLは書き換えない。 |
| FR-12 | Markdown内の相対参照はHTMLへ出力するが、参照先の配置・管理は利用者の責任とする（現行どおり）。 |

## 6. CLI仕様

`--index` は「今回変換したMarkdownだけを目次へ追加する」フラグではない。目次の作成・更新を実行するタイミングを指定するフラグであり、目次作成時には出力先フォルダに存在する目次対象HTMLをすべて評価する。

```bash
# ./docs/report.html を生成した後、./docs/index.html を作成・更新する
md2html ./docs/report.md --index

# ./public/report.html を生成した後、./public/index.html を作成・更新する
md2html ./docs/report.md --output ./public/report.html --index
```

### 基本処理フロー

1. 指定したMarkdownを既存の変換規則に従ってHTMLへ変換する。
2. 変換が成功した場合に限り、出力HTMLの親フォルダを目次生成先として決定する。
3. 目次生成先フォルダ直下の目次対象HTMLを収集し、ファイル名昇順で並べる。
4. 収集結果を基に `index.html` を作成または上書きする。
5. 今回の出力HTMLには「目次へ戻る」リンクを含める。

`--index` およびサイトタイトル指定オプションの正式名称・ヘルプ表記は、詳細設計で確定する。

## 7. 公開API基本設計

CLI限定の機能にせず、Node.js上のTypeScriptおよびJavaScriptから同等の操作を行える公開APIを提供する。CLIの `--index` は、公開APIと同じ仕様に従う。

### API責務

| API | 責務 |
| --- | --- |
| `convertMdToHtml()` | 既存API。Markdown文字列をHTML文字列へ変換する。ファイル入出力および目次生成は行わない |
| `convertMarkdownFile()` | Markdownファイルを出力HTMLへ変換する。目次生成オプションが有効な場合は、出力先フォルダの目次も更新する |
| `generateIndex()` | 指定フォルダ内の目次対象HTMLを収集し、`index.html` のみを作成・更新する。Markdown変換および既存HTMLの書き換えは行わない |

### 利用イメージ

```ts
import { convertMarkdownFile } from "@katsu996/md2html";

await convertMarkdownFile("./docs/report.md", {
  output: "./public/report.html",
  index: true,
  siteTitle: "資料一覧"
});
// ./public/report.html を生成し、./public/index.html を更新する
```

既存HTMLを対象に、目次だけを作成または更新する場合:

```ts
import { generateIndex } from "@katsu996/md2html";

const result = await generateIndex("./public", {
  siteTitle: "資料一覧"
});

console.log(result.indexPath);
console.log(result.entries);
```

`generateIndex()` の結果には、少なくとも生成された目次のパスと、目次に掲載したHTMLエントリの情報を含める。これにより呼び出し元は、更新結果の記録や表示を行える。

### 処理フロー

1. 指定フォルダ直下の目次対象HTMLを収集する。
2. 収集結果を基に `index.html` を作成または上書きする。
3. 既存HTMLには変更を加えない。
4. 作成結果と掲載エントリ情報を呼び出し元へ返す。

公開APIの厳密な関数名、引数・返却値の型、例外およびエラー表現は、詳細設計で確定する。

## 8. 詳細設計時の検討事項

要件変更ではなく、後続の詳細設計で明確化する事項:

- 公開APIの厳密な関数名、引数・返却値の型、例外およびエラー表現。
- 作成日時を取得できない環境での代替値・表示方法。
- 目次生成時に適用する既定スタイルと、既存のCSS・言語・タイトル設定との整合。
- ファイル名の大小文字・日本語・空白・予約文字を含む場合の順序とURLエンコードの具体的な規則。
- 「目次へ戻る」リンクの挿入位置および既存のHTML文書構造との整合。
- CLIにおける `--index` およびサイトタイトル指定オプションの正式名称・ヘルプ表記。
- 目次対象をフォルダ直下に限定する仕様の具体的な境界条件。

## 9. 受け入れ条件

- [ ] `md2html ./docs/a.md --index` の成功後、`./docs/a.html` と `./docs/index.html` が存在する。
- [ ] `md2html ./docs/a.md --output ./public/a.html --index` の成功後、`./public/index.html` が作成または更新される。
- [ ] 既存の `index.html` は `--index` 実行時に上書きされる。
- [ ] 目次には、出力先フォルダ直下に実在する `.html` がファイル名昇順で掲載され、`index.html` 自身は掲載されない。
- [ ] 手作業で作成したHTMLも、存在する限り目次に掲載される。
- [ ] 対応するMarkdownがないHTMLも、存在する限り目次に掲載される。
- [ ] HTMLを削除してから目次を更新すると、削除したHTMLへのリンクは目次から消える。
- [ ] HTML変換に失敗した場合、`--index` による目次更新は実行されない。
- [ ] `--index` で今回変換したHTMLには「目次へ戻る」リンクがある。
- [ ] `generateIndex()` により、HTML変換を実行せずに目次だけを作成・更新できる。
- [ ] 既存の単一Markdown変換APIおよびCLIの基本動作は、`--index` を指定しない限り変更されない。

## 10. 既存仕様への影響

- 既存の単一Markdown変換CLIおよび `convertMdToHtml()` APIの公開インターフェースは変更しない。
- 目次ページも既存のテーマ切替機能と自己完結HTMLの性質を受け継ぐため、既存スタイルとの整合を詳細設計で検討する。
