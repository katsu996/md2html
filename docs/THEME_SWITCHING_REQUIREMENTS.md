# カラーテーマ切替機能 要件定義書

- 対象: `md2html`が生成する既定スタイル付きHTML
- ステータス: 実装候補として合意可能な要件
- 作成日: 2026-08-11

## 1. 目的

生成されたHTMLをどの端末設定で開いても読みやすくする。初期表示では端末のカラースキームを自動反映し、閲覧中は利用者がライトテーマとダークテーマをすぐに切り替えられるようにする。

## 2. 用語と状態

| 用語 | 定義 |
| --- | --- |
| 選択モード | `auto`、`light`、`dark`のいずれか |
| 有効テーマ | 実際に画面へ適用されている`light`または`dark` |
| 端末設定 | ブラウザの`prefers-color-scheme`メディア特性から得られる設定 |

初期状態は必ず`auto`とする。`auto`のときは端末設定がdarkなら`dark`、それ以外は`light`を有効テーマとする。

## 3. 対象範囲

### 対象

- 既定CSSを有効にして生成するすべてのHTML
- ライブラリAPIとCLIの両方から生成されるHTML
- デスクトップとモバイルの主要なモダンブラウザ
- 通常表示、キーボード操作、印刷

### 既定CSSを無効にした場合

`defaultCss: false`またはCLIの`--no-default-css`が指定された場合、本機能のボタン、制御用CSS、制御用スクリプトは出力しない。色の定義を含む既定CSSを明示的に無効化した出力の表示責任は、カスタムCSSの利用者が持つ。

## 4. 機能要件

| ID | 優先度 | 要件 |
| --- | --- | --- |
| FR-01 | Must | 生成HTMLの画面右上に、テーマ切替ボタンを1つ表示する。 |
| FR-02 | Must | ボタンはコンテンツより前面に表示しつつ、見出しや本文を覆わない配置にする。 |
| FR-03 | Must | 初回表示時の選択モードを`auto`とし、darkの端末ではダークテーマ、それ以外ではライトテーマを適用する。 |
| FR-04 | Must | `auto`の間に端末設定が変更された場合、ページの再読み込みなしで有効テーマを追従させる。 |
| FR-05 | Must | `auto`でボタンを1回押すと、現在の有効テーマと反対のテーマへ切り替え、選択モードを`light`または`dark`にする。 |
| FR-06 | Must | 手動選択後はボタンを押すたびに`light`と`dark`を交互に切り替える。 |
| FR-07 | Must | 手動選択中に端末設定が変更されても、選択中のテーマを維持する。 |
| FR-08 | Must | 手動選択は現在のページを開いている間だけ有効とし、再読み込み時は`auto`に戻す。 |
| FR-09 | Must | テーマ切替時にページの再読み込みやスクロール位置の変更を発生させない。 |
| FR-10 | Must | テーマはHTML文書全体と既定CSSのすべての要素に一貫して適用する。 |
| FR-11 | Must | 画像自体の色は反転、減光、加工しない。画像の枠線など既定CSSの装飾のみテーマに合わせる。 |
| FR-12 | Must | 印刷時は選択中のテーマに関わらず現行のライト系印刷スタイルを使用し、テーマ切替ボタンを印刷しない。 |
| FR-13 | Must | 生成HTMLはテーマ機能のために外部CSS、外部JavaScript、Webフォント、画像を読み込まない。 |
| FR-14 | Must | JavaScriptを実行できない環境でも、CSSの端末設定判定による初期テーマは適用する。操作できないボタンは表示しない。 |
| FR-15 | Must | 端末設定を判定できない環境ではライトテーマを使用する。 |

## 5. テーマの適用対象

ライトテーマは現行の既定CSSの見た目を基準とする。ダークテーマでは、少なくとも次の色と装飾を専用のダーク系トークンへ切り替える。

- `html`と`body`の背景、本文色
- 記事カードの背景、枠線、影
- 見出し、強調、通常文、ミュート文字
- リンク、フォーカスリング、チェックボックス
- 引用、インラインコード、コードブロック
- テーブルの見出し、行の境界線、スクロール領域
- 画像の枠線、水平線
- テーマ切替ボタンの通常、hover、active、focus-visible状態
- ブラウザ標準コントロールに適切な`color-scheme`

テーマ色はCSSカスタムプロパティに集約し、色の直接指定を各セレクタに重複させない。ダークテーマの具体的な色値は詳細設計時に確定するが、後述のコントラスト要件を満たすこと。

## 6. UIとアクセシビリティ要件

| ID | 優先度 | 要件 |
| --- | --- | --- |
| UI-01 | Must | ボタンは画面右上から一定の余白を取り、スクロール中も操作できるよう固定表示する。 |
| UI-02 | Must | 狭い画面でも本文に重ならず、画面外へはみ出さない。セーフエリアがある端末ではそれを考慮する。 |
| UI-03 | Must | ポインターとタッチの操作領域は最小44×44 CSS pxとする。 |
| UI-04 | Must | ボタンは`button`要素と`type="button"`を使用し、Tabキーでフォーカスでき、EnterまたはSpaceで操作できる。 |
| UI-05 | Must | フォーカス位置は両テーマで視認できる。 |
| UI-06 | Must | アイコンのみで表示する場合もアクセシブルネームを付与し、現在の有効テーマと次の操作を支援技術が判別できるようにする。 |
| UI-07 | Must | 表示するアイコンは生成HTML内に含め、外部画像やアイコンフォントを使用しない。 |
| UI-08 | Should | ライトテーマ時はダークテーマへの切替を、ダークテーマ時はライトテーマへの切替を想起させるアイコンを表示する。 |
| UI-09 | Must | 初期表示と切替時に大きなレイアウトシフトを起こさない。 |

## 7. 非機能要件

| ID | 分類 | 要件 |
| --- | --- | --- |
| NFR-01 | 視認性 | 通常サイズの文字と背景のコントラスト比は4.5:1以上、大きな文字とUI部品は3:1以上を目標とする。 |
| NFR-02 | 初期表示 | 自動選択はCSSの`prefers-color-scheme`を基本とし、初回描画後に異なるテーマが一瞬表示される現象を起こさない。 |
| NFR-03 | 自己完結性 | テーマのCSS、制御スクリプト、アイコンは生成HTMLの内部に含め、ネットワークリクエストを追加しない。 |
| NFR-04 | 安全性 | 制御スクリプトは`eval`、`Function`コンストラクタ、外部通信、Cookie、Web Storageを使用しない。Markdown由来の文字列をスクリプトとして挿入しない。 |
| NFR-05 | 安定性 | 同じMarkdownとオプションからは、実行時刻や乱数に左右されず同一のHTML文字列を生成する。 |
| NFR-06 | 互換性 | `matchMedia`と`prefers-color-scheme`をサポートする主要なモダンブラウザで動作する。機能が不足する環境ではライト表示へ安全に縮退する。 |
| NFR-07 | カスタマイズ性 | 既定CSSの後にカスタムCSSを適用する現行の順序を維持する。 |

## 8. 生成HTMLの拡張ポイント

- `html`要素に名前空間付きの属性`data-md2html-theme="auto|light|dark"`を設け、現在の選択モードを表す。
- 初期出力の属性値は`auto`とする。ボタン操作後は`light`または`dark`へ更新する。
- 主要なテーマ色は`--md2html-`で始まるCSSカスタムプロパティとし、カスタムCSSから上書きできるようにする。
- テーマ切替ボタンに`md2html-`で始まるclassまたはidを付与し、利用者のカスタムCSSから対象を特定できるようにする。
- 上記の属性名、CSS変数の接頭辞、ボタンのフックは生成HTMLの互換性を保つための公開契約とする。

## 9. 受け入れ条件

| ID | 条件 | 期待結果 |
| --- | --- | --- |
| AC-01 | 端末がdark設定で生成HTMLを新規に開く | 最初の視認可能な描画からダークテーマで表示される。 |
| AC-02 | 端末がlight設定で生成HTMLを新規に開く | 最初の視認可能な描画からライトテーマで表示される。 |
| AC-03 | `auto`のまま端末設定をlightとdarkの間で変更する | 再読み込みなしで表示が追従し、ボタンの状態とアクセシブルネームも更新される。 |
| AC-04 | `auto`で切替ボタンを押す | その時点の有効テーマと反対のテーマになり、`data-md2html-theme`が手動選択値になる。 |
| AC-05 | 手動選択後に端末設定を変更する | 表示テーマは変化しない。 |
| AC-06 | 手動選択後にページを再読み込みする | 選択モードは`auto`に戻り、現在の端末設定が適用される。 |
| AC-07 | Tabでボタンへ移動し、EnterまたはSpaceを押す | フォーカスが視認でき、クリックと同じようにテーマが切り替わる。 |
| AC-08 | 320 CSS px幅の画面で閲覧する | ボタンが画面内に収まり、本文の閲覧と操作を妨げない。 |
| AC-09 | ダークテーマのまま印刷プレビューを開く | 現行のライト系印刷スタイルで表示され、切替ボタンが現れない。 |
| AC-10 | JavaScriptを無効にしてHTMLを開く | 端末設定に合ったテーマで表示され、操作不能なボタンは表示されない。 |
| AC-11 | 既定CSSを無効にしてHTMLを生成する | テーマ切替のボタン、CSS、JavaScriptが含まれない。 |
| AC-12 | カスタムCSS付きでHTMLを生成する | 既定のテーマCSSより後にカスタムCSSが配置され、CSS変数やボタンの見た目を上書きできる。 |
| AC-13 | 同じ入力で複数回HTMLを生成する | バイト列として同じHTMLが得られる。 |

## 10. 検証方針

- ユニットテスト: 生成HTMLの構造、属性、CSS順序、既定CSS無効時の省略、決定性
- DOMテスト: `matchMedia`の結果と変更通知、クリック、キーボード操作、手動選択の維持
- 視覚確認: light/dark×desktop/mobile、初期表示のちらつき、コントラスト、フォーカス、本文との重なり
- 印刷確認: light/darkの両方から印刷プレビューを開いた際のライト化とボタン非表示
- 静的確認: 外部URL、乱数、時刻、Web Storage、Cookie、動的コード実行APIを制御コードが使っていないこと

## 11. 対象外

- 手動選択をページの再読み込み後も保持すること
- Cookie、`localStorage`、`sessionStorage`等への設定保存
- ボタン操作で`auto`へ戻す3状態UI
- APIまたはCLIから初期テーマを固定するオプション
- 利用者が画面上でテーマ色を編集する機能
- Markdownに含まれる画像や生HTML自体の色調整
- テーマ切替UIの複数言語向け文言カスタマイズ

## 12. 既存仕様への影響

- 既定CSSを含む生成HTMLの文字列とDOM構造は変更される。
- 現行の`HtmlDocument.toString()`の決定性と同一インスタンスの再利用性は維持する。
- 既存のCSS適用順序（ブラウザ既定 → 既定CSS → `options.customCss` → `document.customCss()`）は維持する。
- READMEの「JavaScriptへ依存しません」は「外部JavaScriptへ依存しません」に更新し、生成HTML内に固定のテーマ制御スクリプトを含むことを明記する。
- ダークテーマの配色は`DESIGN.md`のデザイン原則と要件`NFR-01`に基づき、実装前に詳細設計で確定する。
